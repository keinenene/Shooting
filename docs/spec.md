# 弾幕シューティング（仮題：STARFALL）仕様書 v2

たたき台（danmaku-spec.md）を元に、項目ごとに決め直した仕様。決定済みの項目だけを書く。

## 1. コンセプト【決定】

- **コア体験**：純粋な弾避け。避けることとグレイズが主役で、システムは王道に絞る
- **規模**：まず1面（道中＋ボス）を作り込んで完成させる。2面以降は後から追加できる構造にしておく
- **世界観**：宇宙・ネオン調。暗い背景に高彩度の弾。キャラクターは出さず、機体・名称・世界観はすべてオリジナル
- **対象**：弾幕経験者。Normalでも手応えがあり、Hardはやり込み向け
- **プラットフォーム**：スマホブラウザ、縦画面固定。PC操作は考慮しない
- **外部依存なし**：ライブラリ・画像・音声素材・外部APIは使わない
- **権利**：既存作品の名称・キャラ・楽曲・固有名詞は使わない

## 2. 操作【決定】

両手持ちが前提。右手で移動、左手で低速とボムを操作する。

- **移動**：相対ドラッグ。画面のどこをドラッグしても、指の移動量だけ自機が動く（指が自機に重ならない）。感度は設定で0.8〜1.6倍
- **ショット**：常に自動で連射
- **低速モード**：左下の専用ボタンを押している間だけ有効。低速化し、判定点を表示し、ショットの間隔を狭めて前方に集める。ドラッグと同時に押せること
- **ボム**：右下の専用ボタンをタップ。ボタン上に指を置いてもドラッグ入力にはしない
- **喰らいボム**：あり。被弾後24フレーム（約0.4秒）以内にボムを押すと被弾を無効化する（タッチの反応遅れを見込んで、たたき台より長め）
- **ポーズ**：右上の小ボタン。メニューは再開／リスタート／タイトルへ。アプリが裏に回ったら自動でポーズする
- **ボタン**：最小56px相当で半透明。設定で左右を反転できる
- **ブラウザ操作の無効化**：スクロール、ピンチ、長押しメニュー、ダブルタップ拡大、テキスト選択

## 3. ゲームシステム【決定】

### 3.1 自機
- 見た目：Canvasのパスで描く三角形系の戦闘機（ネオン調）。初期は1機種。後から機体を追加できるよう、機体定義はデータにする
- 当たり判定：中心の半径2.5pxの円。見た目より十分小さい。低速時は判定点を白く表示する
- 移動速度：通常4.0px/F、低速1.8px/F
- 被弾：残機が1減る。リスポーン演出と約2秒（120F）の無敵がある。残機0でゲームオーバー
- **ボムはミスすると初期値（＝上限）まで補充する**

### 3.2 難易度ごとの初期値（＝上限）
**初期値がそのまま上限になる**。上限の状態で残機やボムが増える出来事が起きても、上限は超えない。

| 難易度 | 残機 | ボム |
|---|---|---|
| Easy | 5 | 3 |
| Normal | 3 | 3 |
| Hard | 2 | 2 |

### 3.3 ショット
- **ショットは前方への直線のみ**。斜めに広がる弾や追尾する弾はない
- **パワーアップによる形の変化はない**。最初から最大の形で撃つ
  - 通常時：平行な直線を広めの間隔で撃つ（5本）
  - 低速時：同じ直線の間隔を狭めて前方に集める（総威力は同じで、狙った1点への威力が上がる）
- 攻撃力はボス戦のタイムボーナスに直結する（3.8、4.3参照）。スコアを狙うほど攻撃力の維持が大事になる
- **攻撃力**：ダメージ上昇アイテムで段階的に上がる（1.0倍〜2.0倍、0.05刻みで最大20段階）
  - ミスで5段階下がり、そのうち一部をアイテムとしてその場にばらまく（拾い直せる）

### 3.4 ボム
- 発動すると約2秒（120F）無敵
- **画面内の敵弾をすべて消し、ボス以外の敵をすべて破壊する**。消した弾は小さなスコア点に変わる
- **ボス（中ボスを含む）には、そのフェーズの割り当て分の一定割合のダメージ**を与える（仮：割り当て分の40%＝4フェーズなら全体の10%）。上限は超えない。耐え切りフェーズには効かない（弾は消える）
- 入手：**特定の中型敵**が確定で落とす（ステージのタイムラインで指定する）
- 上限の状態でボムアイテムを取ると、ボムは増えずスコアに変わる

### 3.5 アイテム
- 種類：**ダメージ上昇（小・大）**、**ボム**、**スコア点**（消した弾から変わったもの）の3つ
- 敵を倒すとその場に出現し、少し上に跳ねてから落ちる
- 自機が画面上部の回収ライン（上から25%）より上に行くと、画面内のアイテムをすべて吸い寄せる
- 低速中は、近くのアイテムを吸い寄せる範囲を広げる

### 3.6 残機の増加
- **ボスを突破すると残機+1**。上限の状態では増えず、スコアに変わる

### 3.7 グレイズ（かすり）
- 敵弾が判定点から12px以内を通過したら、その弾について1回だけ数える（同じ弾では重ねて数えない）
- グレイズ1回ごとにスコアが加算される。小さな効果音と火花の演出を出す

### 3.8 スコア
- 加算源：敵の撃破、**ボスフェーズの素点とタイムボーナス**、ボスフェーズのノーミス・ノーボムボーナス、グレイズ、スコア点の回収、ステージクリア時の残機・ボムのボーナス、上限を超えた残機・ボム
- スコアアタックの柱は**タイムボーナス**。速く倒すほど点が高いので、攻撃力（パワーアップ）を集めて維持する意味がある
- ハイスコアは難易度ごとに保存する

### 3.9 難易度
- Easy / Normal / Hard の3段階。Normalを経験者向けの基準にする
- 弾パターンの数値（弾数・弾速・発射間隔）に難易度係数を掛けて作る。難易度ごとに別の定義は作らず、必要な箇所だけ個別に上書きする

## 4. ステージ・弾幕【決定】

### 4.1 1面の位置づけ
- **1面だけで遊べる完成品**にする。弾幕の種類と殺意を一通り味わえる密度にする
- 後で面を足すときは、この面を「最初の面」として難しさを調整し直す
- ステージは「タイムラインのデータ＋背景設定」で定義する。面を足すときはファイルを追加するだけで済むようにする

### 4.2 1面の流れ（約3〜4分）
```
道中前半（約45秒）→ 中ボス（1フェーズ・約30秒）→ 道中後半（約45秒）→ ボス（4フェーズ）→ リザルト
```
- 道中：敵の波をタイムラインで定義する（フレーム番号、敵の種類、出現位置、軌道、弾パターン、落とすアイテム）
- 中ボス：1フェーズだけ。撃破か時間切れで退場する（時間切れでもゲームは続く）。削り切るとタイムボーナスがあり、ボムアイテムを確定で落とす

### 4.3 ボス
- **通常フェーズ×3＋最後の耐え切りフェーズ**の計4つ
- 各フェーズに制限時間（40〜60秒）、名前、固有の弾幕パターンがある

**体力とフェーズの関係**
- ボスの体力は1本で、**フェーズごとに削れる量の上限**がある。フェーズ数で等分する（4フェーズなら各25%）。ステージのデータで配分を上書きできる
- 通常フェーズ：そのフェーズの割り当て分（25%）を削り切ると、画面内の弾をすべて消して次のフェーズへ進む。上限を超える分のダメージは次のフェーズに持ち越さない
- 制限時間まで耐え切った場合も**フェーズクリア**。削り切れていなくても、体力はそのフェーズの区切りまで減る
- **耐え切りフェーズ**（最後）：攻撃もボムも効かない。時間切れまで耐えると最後の25%が削れ、ボスを撃破する
- つまり、**最後まで生き残れば必ずボスを倒せる**。腕前の差は、各フェーズを速く終わらせることで生まれるスコアの差に表れる
- 体力ゲージにはフェーズの区切りを示す線を引く

**フェーズのスコア**
- **素点**：フェーズをクリアすると、削り切りでも時間切れでも必ず一定の点が入る
- **タイムボーナス**：削り切った場合だけ、素点に「残り時間×係数」を加える
- **ノーミス・ノーボムボーナス**：そのフェーズを被弾もボムもなしでクリアすると加点する
- 耐え切りフェーズは素点のみ（時間いっぱい耐えるので、タイムボーナスはない）

**演出・記録**
- フェーズを切り替えるときは画面内の弾を消し、フェーズ名をカットイン風に表示する（文字と図形のみ）
- フェーズごとのクリア記録を保存する

### 4.4 1面のテーマ（仮）
- 舞台：小惑星帯から宇宙ステーションの外縁へ
- 背景：パララックススクロールする星と、手続き生成の小惑星シルエット。低負荷にする

### 4.5 弾幕エンジン（最重要）
弾パターンは**データ駆動**で定義し、コードを書かずにパラメータの組み合わせで量産できるようにする。

**弾の属性**
- 位置、速度（角度＋速さ）、半径、色、見た目（小弾・中弾・大弾・米粒・針・楔）
- 加速度（速さの変化）、角速度（曲がる弾）、速さの下限と上限
- 寿命、画面外で消える（画面外に出て戻ってくる弾は余白を設定する）
- 発射後に挙動を変える**イベント**：一定フレーム後に減速／停止／再加速／分裂／自機狙いに向き直す

**パターン定義の例**
```js
{
  id: "spiral_01",
  emitter: {
    interval: 4,            // 何フレームごとに撃つか
    count: 3,               // 1回に撃つ弾数（放射状）
    spread: 360,            // 放射する角度の範囲（度）
    baseAngle: { type: "rotate", start: 0, speed: 2.5 }, // 基準の角度が毎回回る
    aim: false,             // trueなら自機を狙う
    bullet: { type: "small", color: "#4df", speed: 2.2, accel: 0, curve: 0 }
  },
  duration: 600
}
```
- 基準角度の動き：固定／回転／往復（sin）／自機狙い／ランダム
- 複数のエミッターを同時・時間差で重ねられる（1フェーズで複数のパターンを使う）
- 発射位置は、ボス本体からのずらし量やボスの周りを回る子機（ビット）として指定できる
- 難易度係数は `count`・`speed`・`interval` に掛ける

**最低限の12パターン**
円形、扇形、n-way自機狙い、螺旋、二重螺旋（逆回転）、ランダム散布、壁（横一列）、加速弾、減速→再加速弾、曲がる弾、分裂弾、花火型（一定距離で円形に分裂）

### 4.6 練習モード
- **解放制**：一度到達したフェーズ（道中前半／中ボス／道中後半／ボスの各フェーズ）を選んで挑戦できる
- フェーズごとに突破数／挑戦数を記録する

### 4.7 デバッグ用
- `?debug=1` でパターンテスト画面を出す。パターンやボスのフェーズを選んで即再生できる
- 弾数、FPS、当たり判定円の表示を切り替えられる。無敵モードもある

## 5. 技術・画面・演出【決定】

### 5.1 技術
- HTML＋CSS＋バニラJavaScript（ES Modules）。**ビルドなし**で、ファイルを置くだけで動く
- 描画：Canvas 2D。内部解像度は**360×640固定**で、画面に合わせて拡大縮小する（devicePixelRatio対応）。縦長の端末では上下の余白にHUDとボタンを置く
- 更新：固定タイムステップ（1/60秒）。描画とロジックを分け、端末のフレームレートに挙動が左右されないようにする
- 乱数：シード付き乱数（mulberry32）。将来のリプレイ機能のため `Math.random` は直接使わない
- 弾・敵・パーティクル・アイテムは**オブジェクトプール**で管理し、毎フレーム `new` しない
- 性能目標：弾1000発で60fps（受け入れ基準はスマホ実機で800発前後）
- 当たり判定：円同士の距離のみで判定する（距離の2乗で比べる）。必要になったら空間グリッドを入れる
- サウンド：Web Audioで合成する。**効果音＋簡易BGM**（道中用・ボス用のループ曲。曲は楽譜データとして持つ）。初回タップで AudioContext を開始する
- セーブ：localStorage（ハイスコア、練習モードの解放状況と記録、設定）。読み書きは try/catch で囲む
- PWA：manifest.json と Service Worker でオフラインでも動き、ホーム画面に追加できる
- 画面スリープ防止：Wake Lock API（対応端末のみ）
- 配信：**GitHub Pages**（keinenene/shooting）。スマホでURLを開いて確認する

### 5.2 画面遷移
```
タイトル → 難易度選択 → ステージ → リザルト → タイトル
         ├→ 練習モード（フェーズ選択）→ ステージ → リザルト
         └→ 設定
```
- 設定項目：効果音／BGMの音量、移動感度、ボタン配置の左右反転、判定点の常時表示ON/OFF、画面振動ON/OFF

### 5.3 HUD
- 上部の余白：スコア、ハイスコア、残機、ボム、攻撃力、グレイズ数
- ゲーム領域の上端：ボスの体力ゲージ（細め）、フェーズ名、制限時間
- 下部の余白：低速ボタン（左）とボムボタン（右）

### 5.4 演出
- 弾・自機・敵はネオン調。**弾が見やすいことを最優先**にし、弾は他のどの要素よりも手前に描く
- 敵の撃破・被弾・ボム・グレイズでパーティクルを出す（プールで管理）
- ボス登場とフェーズ切り替えで、カットイン風の文字演出（文字と図形のみ）
- 画面振動は設定でON/OFFできる。点滅は控えめにする（光過敏への配慮）

### 5.5 ファイル構成（案）
```
/index.html

/sw.js
/src
  main.js         起動、ゲームループ
  config.js       調整用の定数（速度、判定、残機、無敵時間、難易度の係数など）
  game.js         状態管理、シーン遷移
  input.js        タッチ入力（相対ドラッグ、ボタン）

```

## 6. マイルストーン【決定】

各段階で動く状態を保ち、GitHub Pagesでスマホ実機から確認できるようにする。

1. **M1 操作の気持ちよさ**：相対ドラッグ移動、低速ボタン、自動ショット、固定タイムステップ、画面の拡大縮小、GitHub Pagesでの配信。ここで操作感を実機で確認する
2. **M2 弾幕エンジン**：プール、パターンのデータ駆動定義、基本12パターン、判定点・被弾・グレイズ、デバッグ画面（パターンテスト、FPS、弾数）
3. **M3 ボス戦**：ボス1体（4フェーズ）、HUD、残機、ボム、喰らいボム、フェーズ切り替えの演出
4. **M4 1面を通しで遊べる**：道中タイムライン、中ボス、アイテム、攻撃力、スコア、難易度、タイトル／リザルト、サウンド、セーブ
5. **M5 仕上げ**：練習モード、設定画面、PWA化、性能の調整、バランスの調整
6. **以降**：2面以降の追加、機体の追加、リプレイ

**まずM1とM2までを作り、確認を求める。** 実装前に、M1・M2の範囲で設計の要点（ファイル構成、弾のデータ構造、ゲームループ）を短く提示する。

## 7. 受け入れ基準

- スマホ実機で、弾800発前後の場面でも体感60fpsを維持する
- 操作中に画面がスクロール・拡大・選択されない
- 当たり判定が見た目より小さく、低速時に判定点が見える
- 難易度を変えると、弾幕の密度と速度が目に見えて変わる
- 新しい弾パターンを、パターン定義を足すだけで増やせる
- ネットワークを切ってもPWAとして起動できる

## 8. 開発上のルール

- 調整が必要な数値は `config.js` にまとめる
- コメントは日本語で簡潔に
- READMEに、起動方法と実機での確認手順（GitHub Pages／同じWi-Fi内でのローカル配信）を書く
- 不明点は仮置きで進め、仮置きした内容を最後に列挙する
